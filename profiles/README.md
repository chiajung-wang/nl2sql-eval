# `profiles/` — the version-controlled field-description cache (Step 12, #140)

Profiling-derived field metadata (Shkapenyuk et al., arXiv:2505.19988v2 §2.1). One
JSON artifact per db, keyed by `"table.column"`, treated with the **same discipline
as `prompts/`**: checked in, reviewed, diffable. The live pipeline only *reads* these
files (`nl2sql.profiling.cache.load_field_descriptions`); it never summarizes at
request time, so a run is reproducible.

**Load-bearing boundary (CLAUDE.md §4/§7).** These descriptions are **content for the
generate prompt only** — they ride into the rendered schema the generator sees. They
are **never** read by `guard.py` or `eval/compare.py`, which stay deterministic and
data-independent, so scoring is untouched.

## Format

```json
{
  "db_id": "<db>",
  "generated_by": "<model / provenance note>",
  "fields": {
    "table.column": { "short": "<terse gloss, for schema linking>",
                       "long":  "<meaning + format, for SQL generation>" }
  }
}
```

- `short` feeds schema **linking** (#138) — kept terse so many fields fit.
- `long` feeds SQL **generation** — the format/meaning detail.
- Keys are casefolded `table.column`; the file is sorted + pretty-printed so a
  refresh is a minimal, reviewable diff.

## How an artifact is produced

The three-stage pipeline (`nl2sql.profiling`):

1. **Deterministic profile** — `profiler.profile_db(engine, db_id)`: per-column counts,
   NULL/non-NULL, distinct, value shape (length, character class, common prefix,
   min/max), top-k. No LLM.
2. **Mechanical English** — `render.render_column_english(profile)`: the profile as
   plain facts. No LLM.
3. **LLM summarization** — `summarize.summarize_db(client, profile, model=…)`: the
   model interprets the English into `short` + `long`. This is the **only** step that
   calls a model, and it is **offline precompute** (deferred, gated on a key):

   ```
   uv run python -m nl2sql.profiling.summarize --db-url <sqlalchemy-url> --db-id <db> --model <model>
   #   --dry-run  prints the deterministic English only (no model call, no write)
   ```

   On a malformed reply the summarizer degrades to the deterministic English as the
   `long` description — still valid profiling metadata, just not model-polished.

## Metadata source (the #140 A/B axis)

`METADATA_SOURCE` (env, like `MODEL`/`RUN_CONFIG`) selects how the harness/demo build
the schema index — `supplied` (default, current behaviour), `profiling`, or `fused`
(supplied + profiling, the paper's best). Resolved by
`cache.resolve_column_descriptions(db_id, source)` → the `column_descriptions=` map
for `build_schema_index`. A db with no artifact here degrades to `supplied` cleanly.
