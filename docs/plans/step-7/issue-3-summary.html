1 Overview

Model selection as a measured artifact: one harness runs the frozen slice through every model and lays accuracy, cost, and latency side by side — through the LiteLLM boundary, so a provider is just a string.

With LangGraph (#50) and the LiteLLM boundary (#51) in place, the Step-7 DoD turns "cost-latency-quality trade-offs" into a table. eval.eval_cross_provider runs the import-shared pipeline over the frozen BIRD slice once per model in CROSS_PROVIDER_MODELS and reports pass@1 / pass@k × cost × latency per row. One OPENROUTER_API_KEY reaches many providers via openrouter/<provider>/<model>.

The work here is the apparatus and its two honesty rails; the live numbers are a keyed run away (deferred, below). pass@1 is derived from each pass@k run's first attempts — the sampling-noise-free twin, same convention as Step 5.

2 The two honesty rails

Cost basis noted per row

  • An openrouter row is priced by OpenRouter's own reported cost (surfaced by LiteLLM on the response), not the direct-list table
  • A direct anthropic/… row uses the dated list table in eval.cost
  • The two aren't comparable dollar-for-dollar — so the table has a cost basis column; a missing cost renders n/a, never a fabricated number

OpenRouter routing pinned

  • allow_fallbacks: false via the #51 extra_params hook
  • So a frozen-slice row can't silently switch backend (or quantization) mid-run
  • Repeatability is a Step-7 / PRD §9 invariant — the seeded slice must mean the same thing twice

Capturing the authentic OpenRouter price needed a thin extension of the boundary: LLMResponse.cost_usd (from LiteLLM's response_cost) → state.meta["cost_usd"] → CaseResult.provider_cost_usd → BatchReport.provider_cost_usd. Additive, defaults preserve every existing behaviour — and it's the only way to price OpenAI/Google rows the Claude-only list table can't.
