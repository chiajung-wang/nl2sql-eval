LiteLLM provider boundary — backend selectable by model id

Author: Chia-Jung Wang (@chiajung-wang) Issue: #51 · builds on #50 Branch: step-7/issue-51-litellm-swap → main

1 Overview

One seam, many backends. The pipeline stops knowing about a vendor SDK and starts depending on a single complete call — so a provider is now just a string.

Step 1 hard-wired the Anthropic SDK into the generate stage. Step 7 (issue #51) replaces it with the nl2sql.llm boundary backed by LiteLLM — mirroring JKOPay's actual "LiteLLM Gateway" stack. The pipeline now imports only a tiny LLMClient protocol; LiteLLMClient adapts LiteLLM's OpenAI-shaped response and normalizes token usage so the harness prices any backend identically. This is the plumbing that makes the cross-provider cost/accuracy table (#52) trivial.

The design choice that matters: the backend is selected purely by the model identifier — anthropic/… for a direct key, openrouter/… to reach many models through one key. OpenRouter is a provider behind LiteLLM, not a replacement; there is zero provider branching in our code.
