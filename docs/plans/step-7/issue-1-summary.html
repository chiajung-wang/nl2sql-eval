1 Overview

Introduce the framework where it earned its place — and use the harness to prove the refactor changed nothing.

Steps 1–6 ran on a hand-rolled while loop on purpose: framework churn must never mask logic bugs while the logic is still being proven. With the pipeline now measured end-to-end, Step 7 re-expresses that proven loop as a compiled LangGraph StateGraph. The architecture already was a graph — a capped correction loop, a retrieval re-trigger, and terminal-state branching — so this is a genuine fit, not framework-for-its-own-sake.

The discipline that matters: this is a behavior-preserving refactor. run_pipeline keeps its exact signature and RunState return, so no caller (eval harness, demo, tests) changes; the conditional edges encode exactly the branches the hand-rolled loop had. The whole offline suite — which drives run_pipeline with an injected fake client — proves the loop, the not-found re-trigger, the end-to-end guard, and the adaptive gate all behave identically.

2 The translation — node-by-node, no behavior change

The hand-rolled while loop mapped onto LangGraph with no semantic drift. The mutable RunState is one channel (the stage functions mutate it in place, as before); the loop-local bookkeeping rides alongside it; static per-run inputs pass via config["configurable"] so the graph compiles once at import and every question reuses it.

The scope-retry predicate (guard_rule == "table_scope" and schema_index is not None and attempts < budget), the floor = max_tables * 2**re_retrievals widening, and the pre-correct hint capture are all reproduced verbatim. Both pipeline exits (raw verified result; presented/redacted result) and every terminal state are untouched — and the terminal-state classifier still lives in the harness, never in graph.py or state.py.
