Plan · Step 7 · Framework / provider

Swap in LangGraph + LiteLLM; cross-provider table

Phase: Framework / provider (only AFTER logic is proven) Depends on: Steps 1–6 (fully working, measured pipeline) Unblocks: Step 8 (wire obs on the framework pipeline)

1 Headline & goal

Introduce the framework where it earns its place — and use the harness to prove the refactor changed nothing.

Refactor the now-proven hand-rolled loop into LangGraph, swap the direct LLM call for LiteLLM (multi-provider), and produce a cross-provider comparison table. Deferred to here deliberately so framework/provider churn never masked logic bugs during Steps 1–6. The harness is the safety net: same-or-better numbers prove the swap was behavior-preserving.

2 What to build

LangGraph refactor (pipeline/graph.py)

  • Re-express the state machine as LangGraph nodes + conditional edges — the architecture already is a graph (correction loop, re-trigger, terminal branching).
  • Hand-rolled remains a defensible permanent fallback if LangGraph friction threatens the timeline.

LiteLLM swap (llm/)

  • Replace the direct single-provider call with the LiteLLM abstraction — mirrors JKOPay's "LiteLLM Gateway" stack.
  • Makes multi-provider comparison trivial; default stays a latest-capable Claude model.

Cross-provider comparison

  • Run the harness across providers/models → a table of accuracy × cost × latency per model.
  • Turns "model selection / cost-latency-quality trade-offs" into a concrete eval artifact.

6 Pitfalls

PitfallSeverityWhy it bites
Accepting silent regressions correctness If numbers regress after the swap, the refactor broke something — investigate before proceeding.
LangGraph API churn derailing timeline scope Hand-rolled is a defensible permanent fallback. Don't let framework friction stall the project.
Squashing the git history narrative The hand-rolled → framework history is itself a story asset — "I introduced LangGraph when the state machine earned it."
Refactoring before logic is proven ordering This step is deliberately after Steps 1–6 so framework churn never masks logic bugs.

7 Guardrails for this step

Never (anti-patterns)

  • Accept silent regressions after the swap.
  • Change behavior while "just refactoring" — the harness must show parity.
  • Break the two pipeline exits or terminal states in the port.
  • Squash the hand-rolled → framework history.

Always

  • Run the harness before and after; prove parity.
  • Default to a latest-capable Claude model; others via config.
  • Keep the pipeline import-shared (no demo fork).
  • Record the cross-provider table in RESULTS.md.
