1 Headline & goal

Make the project legible — and assemble the blog from the trail of committed results.

Make the project readable to a reviewer and tell its story. Split the work by risk: README + blog post are non-negotiable; the thin demo reveals the wrapper; BigQuery is an optional reach that must never block the parts that make the project legible. The blog writes itself only if the results log was kept honestly from Step 3 (PRD §9/§11, CLAUDE.md §6).

2 What to build

README — the front door

  • Lead with the thesis; show the architecture diagram; surface the headline findings.
  • How to run it; each claim links to its RESULTS.md entry / commit.

Technical blog post

  • Inversion → comparator → correction → retrieval → guardrails → operations → honest limits.
  • Every number links to its committed run — the rigor is the story.

Thin demo UI (apps/demo/)

  • Streamlit, isolated dep group; reveals the wrapper — guardrail decision, retry count, cost, terminal state.
  • Imports the same shared pipeline — no fork, no drift.

BigQuery connection optional reach

  • Cloud-warehouse checkbox via sqlglot transpilation. Real integration risk (auth, dialect, cost).
  • If it slips, ship without it — an unreadable repo is fatal, a missing cloud checkbox is not.

6 Pitfalls

PitfallSeverityWhy it bites
BigQuery delaying README/blog legibility Don't let BigQuery's integration risk delay the README/blog — they're what make everything else legible.
Reconstructing numbers from memory rigor The blog writes itself only if the results log was kept honestly from Step 3; skipped entries mean reconstructing from memory (the exact failure this discipline prevents).
A slick chatbot demo narrative Keep the demo honest — revealing the machinery is the point; a chatbot that hides the wrapper undersells the project.
Demo forking the pipeline integrity The demo must import the same shared pipeline as the harness — no drift between what's demoed and what's measured.

7 Guardrails for this step

Never (anti-patterns)

  • Let BigQuery block the README/blog.
  • Report a claim without a linked RESULTS.md entry.
  • Ship a demo that hides the wrapper.
  • Fork the pipeline for the demo.

Always

  • Lead with the thesis; link every claim to its commit.
  • Keep the demo honest — reveal guardrail/retry/cost/terminal state.
  • Treat BigQuery as quarantined optional reach.
  • Note publication (and any BigQuery result) in RESULTS.md.
