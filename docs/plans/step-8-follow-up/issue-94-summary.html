1 Overview

Let the tool grade its own wiring. Step 8 connected the obs/ seams to Langfuse and proved a failing question is diagnosable from its trace (#54–#56). This follow-up installs the official Langfuse skill (langfuse/skills) and runs its instrumentation.md baseline audit over that wiring.

The audit scored the instrumentation well already — model / tokens / cost on the generate generation, correct span hierarchy and observation types, PII masking, and (it turns out) flush() already covered by the SDK's own atexit. It surfaced exactly one unmet baseline — the root pipeline span captured neither the question nor the result, so a trace wasn't legible at its top level — and, once live keys went in, one silent blocker: a region/host mismatch.

2 What the audit found

baseline checkverdict
model name · token usage · costpass — on the generate generation span
span hierarchy · observation typespass — pipeline → retrieve → generate → guard → execute → correct → redact
sensitive data maskedpass — shapes / counts / SQL only, never result rows
flush() on exitpass — Langfuse v4 self-registers an atexit shutdown
trace input / outputgap — the root pipeline span had no input, no output

The silent blocker. The Python SDK reads LANGFUSE_HOST; the langfuse-cli reads LANGFUSE_BASE_URL. With only LANGFUSE_BASE_URL=https://jp.cloud.langfuse.com set, Langfuse() defaults to EU cloud and the JP keys fail to authenticate — no traces, no error. The skill calls this out; it would have blocked every trace regardless of the wiring.

The root span now records the NL question as the trace input and the presented (redacted) result's shape as the output — counts, the generated SQL, attempts, the guard flag. Never raw rows: scoring stays upstream of redaction, and only the masked exit is read for the output (CLAUDE.md §5.3). The question is the user's own message — distinct from PII pulled from the database.
