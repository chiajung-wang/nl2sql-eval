One eval batch, one Langfuse Session

Author: Chia-Jung Wang (@chiajung-wang) Issue: #96 Branch: step-8-follow-up/issue-96-session-id-batch-grouping → main

1 Overview

The deferred next slice from #94, cashed. #94 left a seam — obs.trace_attributes(session_id=…) — but nothing threaded a session, so every question's trace stood alone. This change groups a whole eval batch into one Langfuse Session, so an eval run becomes a single comparable unit in the Sessions view.

The v4-idiomatic part: no run_pipeline signature change. Wrapping the harness's batch loop in trace_attributes(session_id=…) is enough — propagate_attributes nests every per-question trace under the session automatically. A stable, readable id (<mode>:<model>:<prompt>:<UTC date>) keeps same-day re-runs comparable and sends A/B modes to sibling sessions.

propagate_attributes attaches the session_id to the current and all child observations in scope — so every per-question pipeline trace created inside the loop inherits it. The session id is a run identifier (mode / model / prompt / date) — never PII (CLAUDE.md §5.3).
