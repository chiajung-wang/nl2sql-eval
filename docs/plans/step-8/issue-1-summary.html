Wire pipeline stage seams to Langfuse spans

Author: Chia-Jung Wang (@chiajung-wang) Issue: #54 Branch: step-8/issue-54-langfuse-spans → main

1 Overview

Connect the seams, don't instrument from scratch. Steps 1–7 each added a thin obs seam (stage_span) as the stage was built — instrument-as-you-build. Step 8's tracer bullet wires those existing seams to Langfuse, so every run becomes one trace whose child spans mirror the stages.

One stage_span change does it: in addition to its structured start/end logs, it now opens a Langfuse observation named after the stage. Nesting is automatic — the root pipeline span opens the trace and every stage span entered inside it becomes a child via the Langfuse / OpenTelemetry context. The generate stage opts into a generation-typed span so token usage and provider cost promote to Langfuse's native usage_details / cost_details axes — the cost basis the pass@1-vs-pass@k analysis already reads off state.meta, now also on the trace.

The wiring is offline-safe by construction and honors the defer-API-key discipline: live trace capture waits for a key, but the seam is proven offline today.

2 What the seam does now

The contract is unchanged: callers attach only safe fields (counts, the generated SQL, the guard verdict, token/cost numbers) — never result rows (CLAUDE.md §5). Those now flow to both the log event and the span.

one trace per runroot pipeline span opens the trace; stage spans nest under it automatically (OTel context)
latencyduration_ms recorded on every span's metadata
tokens & costgenerate → as_type="generation"; extra tokens/cost promote to usage_details / cost_details + the model
offline defaultget_client() returns a live client only when both LANGFUSE_* keys are set; else None → pure log-only seam, no network
never breaks a runmissing/erroring Langfuse is swallowed; a stage that raises marks its span level="ERROR" and re-raises

redact is intentionally absent from the span list — it is still a stub; it gains a real seam (and the redacted-logging enforcement) in #55.
