Plan · Step 8 · Operations

Wire observability seams to Langfuse; enforce redacted-logging

Phase: Operations Depends on: Steps 1–7 (thin obs seam per stage) Unblocks: Step 9 (CI posts deltas) · Step 10 (trace visuals for the blog)

1 Headline & goal

Make any failure diagnosable from its trace — without ever logging raw PII.

Wire the thin logging seams (added stage-by-stage during Steps 1–7) to Langfuse, and enforce redacted-logging discipline. Because the seams already exist, this is "connect and enforce," not "instrument seven steps from scratch" — honoring the instrument-as-you-build principle. The score-upstream / log-downstream two-exit rule (CLAUDE.md §3/§5) is a real regulated-industry talking point — it must be verified, not assumed.

6 stage spans per trace
cost/latency/tokens captured natively
0 raw PII in logs/traces
any failure diagnosable from its trace

2 What to build

obs/ → Langfuse

  • Wire each stage's existing seam to a Langfuse span; one run = one trace whose spans mirror retrieve · generate · guard · execute · correct · redact.
  • Capture cost / latency / tokens natively (feeds the pass@1-vs-pass@k cost analysis).

Redacted-logging enforcement

  • Score upstream of redaction; log/present downstream of it. Traces record the redacted (presented) result only.
  • Verify the two-exit discipline holds in the wired pipeline — raw PII must never reach Langfuse.

Trace-driven debugging

  • Open a failing question's trace and see, per span, what each stage did: retrieved tables, generated SQL, guard verdict, attempts, terminal state.
  • Capture an example trace for the blog (an "operate the system" visual).

Every run becomes a trace whose spans mirror the six stages, carrying cost/latency/tokens. Scoring reads the raw verified result upstream of redaction; only the presented (redacted) result is ever logged or traced — raw PII never reaches Langfuse.

6 Pitfalls

PitfallSeverityWhy it bites
Assuming the redact-vs-raw exit holds PII The redacted-vs-raw exit discipline is a real production concern and a strong regulated-industry talking point — verify it actually holds, don't assume.
Bulk-retrofitting instrumentation process Don't retrofit obs from scratch; if a seam is missing from an earlier step, add the seam, then wire it.
Logging the raw verified result PII Only the presented (redacted) result is logged/traced. Scoring happens upstream and must never corrupt redaction.

7 Guardrails for this step

Never (anti-patterns)

  • Let raw PII reach logs, traces, or the presented result.
  • Assume the two-exit discipline holds — verify it.
  • Bulk-retrofit instrumentation instead of wiring existing seams.
  • Move scoring downstream of redaction.

Always

  • One run = one trace, spans mirroring the six stages.
  • Capture cost / latency / tokens per span.
  • Log/present only the redacted result.
  • Confirm a failing question is diagnosable from its trace.
