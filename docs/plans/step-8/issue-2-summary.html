Redacted-logging enforcement — the presented pipeline exit

Author: Chia-Jung Wang (@chiajung-wang) Issue: #55 Branch: step-8/issue-55-redacted-logging → main

1 Overview

Score the truth; show — and log — only the redaction. The pipeline has two exits (CLAUDE.md §3), and Step 8 makes the second one real. The raw verified result is what the harness scores against gold, upstream of redaction. The presented result is post-redaction — the only result the demo shows a user or that anything writes to logs or traces.

This issue implements the redact stage and wires the discipline end-to-end. redact produces the presented exit from the raw rows without ever touching the raw rows, so masking can never corrupt scoring. The masking is deterministic (a fixed mask, no LLM, no value-sniffing), column-aware (it blanks the values of PII columns), and schema-driven (the PII column set is parsed from the schema's own -- PII annotations).

The plan's pitfall — "verify it actually holds, don't assume" — is met with a non-vacuous end-to-end test: a real PII value flows through the full pipeline, and the secret is asserted absent from every captured span and every log line, while the raw exit still holds it.

2 Two exits, one stage

execute populates the raw exit (result_rows/result_columns). run_pipeline then runs redact as the final stage, populating the presented exit (presented_rows/presented_columns) — a copy with every PII column's value replaced by the fixed MASK. The harness keeps scoring result_rows; the raw exit is never written by redact.

concernhow it's enforced
scoring upstreamscore_run reads result_rows (raw); redact writes only presented_* — a copy, never an alias
schema-driven policyRedactionPolicy.from_ddl parses -- PII markers (excludes the weaker PII-adjacent label)
column-aware maskmatch by normalized output-column name (alias- and case-insensitive); blank with a constant — original length/format don't survive
import-shareddemo & harness pass the same policy into the same run_pipeline; NO_REDACTION (default) masks nothing — the BIRD path
span leaks nothingthe redact span records counts + the names of masked columns (schema metadata), never a value

Honest limit (pinned by a test): matching is on the output column name, so a PII column aliased to a non-PII name (SELECT email AS contact) escapes. Closing that needs sqlglot projection resolution — deeper than this stage — so it is documented and regression-tested as a conscious trade-off, not a silent hole.
