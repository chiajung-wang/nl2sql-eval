2 The rigor fix: one run, not two

The first cut ran pass@1 and pass@k as two independent stochastic batches. That conflates the value of correction with sampling noise — a question can flip wrong→right just by resampling the model, with no correction involved. (A throwaway two-run pass on this slice showed a spurious +0.060 gap from exactly this noise, with only one real correction firing.)

The fix — derive_pass1_report — runs pass@k once and derives pass@1 from its first attempts. The loop only retries on an execution error, so attempts > 1 means attempt 1 errored. Therefore:

pass@1-correct ⟺ (final-correct AND attempts == 1)

Zero cross-run noise. The gap is now exactly the set of questions an attempt-1 execution error recovered from — nothing else.
