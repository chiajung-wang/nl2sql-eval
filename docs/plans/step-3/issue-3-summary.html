1 Overview

Phase 1's Definition of Done: the project's thesis made concrete — the first real, trustworthy pass@1 on BIRD, traceable to its exact config and commit.

Issues 1 and 2 built the batch harness and froze the slice. This issue runs the validated Step-2 comparator over that frozen slice and lands the first number in RESULTS.md. From here on the results log is mandatory: no step is done until its number is committed with model, slice ID, prompt version, date, and commit.

The number is deliberately the naive schema-dump baseline — whole schema in the prompt, one generation, no retrieval, no self-correction. A modest number here is a feature of the narrative: it is the "before" that Step 6's retrieval lift and Step 5's pass@k will be measured against.

3 Key changes

eval/eval_bird.py — the live BIRD job

  • Loads the frozen slice, binds the shared run_pipeline per question with its tagged SQLite db + dialect + evidence, runs the batch, prints pass@1 and the terminal mix.
  • Runnable offline as a job: uv run python -m eval.eval_bird.

prompts/generate/v2.jinja + generate.py

  • New dialect-aware prompt: names the SQL flavor (SQLite on BIRD, PostgreSQL on payments) and folds in BIRD's per-question evidence hint.
  • PROMPT_VERSION = "generate/v2" — the version recorded with every number.

eval/compare.py — the dialect scoring fix

  • Gold SQL is parsed dialect-aware ((None, "sqlite")) for top-level ORDER BY detection — BIRD's backtick-quoted identifiers the generic parser rejects no longer silently fall back to order-insensitive.

eval/metrics.py · graph.py · tests

  • Shared summary_lines so payments and BIRD print the same shape; dialect threaded through the pipeline.
  • tests/test_eval_bird.py + a dialect-parse case in test_compare.py.

5 What this number is not

  • Not state-of-the-art — it is the naive baseline (no retrieval, no correction) that later lifts are measured against. Step 5 reports the pass@1 → pass@k gap; Step 6 the naive → retrieval lift.
  • Not just one number — the harness also reports the terminal-state mix and pass@1 by difficulty; the failure taxonomy is the analytical payload.
  • Not a remembered claim — it is committed to RESULTS.md with full config, the start of the mandatory results discipline.
