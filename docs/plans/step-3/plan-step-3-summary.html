1 Headline & goal

Produce the first trustworthy measured claim.

Wire the batch harness and produce the first real pass@1 on BIRD — using the now-validated comparator from Step 2. This is the project's thesis made concrete: a measured claim, not a working toy. With no self-correction yet, pass@1 is the only meaningful metric; the number is explicitly the naive schema-dump baseline — the "before" that Step 6's retrieval will lift (CLAUDE.md §6, PRD §9).

2 What to build

eval/harness.py — the batch runner

  • Iterate a test set → invoke the shared-import pipeline (never a copy) → score each via compare.py → bucket the terminal state.
  • Batch-capable, offline, repeatable — invokable as a job, not only behind the demo. This is what enables prompt-CI later.
  • Emit pass@1.

eval/datasets/bird/ + frozen slice

  • Loader/adapter for BIRD: SQLite, file-per-db; run each question against its tagged db (single-db per run; no routing).
  • Frozen, seeded slice from smaller-schema dbs first, checked in as an explicit ID list.
  • Small-schema-first keeps the baseline honest — large schemas overflow the prompt and tank accuracy for reasons unrelated to generation.

eval/metrics.py — aggregation

  • Accuracy aggregation + the terminal-state classifier (lives here, not in state.py — CLAUDE.md §3).
  • Every run buckets into exactly one terminal state.
  • Computes pass@1 over the batch.

5 Done when & results log

Done when: you have your first real pass@1 on the frozen, small-schema BIRD slice, produced by the validated comparator.

The results log starts here and is now mandatory. Append to RESULTS.md: date, model, slice ID, prompt version, commit, pass@1, and a one-line note ("naive schema-dump baseline, small-schema slice"). From here on, no step's done-when is met until its number is in RESULTS.md with full config (CLAUDE.md §6).

6 Pitfalls

PitfallSeverityWhy it bites
Large-schema dbs in the slice baseline With no retrieval, the whole schema is dumped into the prompt; large schemas overflow context and tank accuracy for reasons unrelated to generation — contaminating the baseline.
String-comparing SQL correctness Only result sets, via compare.py. Two different queries can be equally correct.
Pipeline drift integrity The harness must invoke the same pipeline as the demo (shared import). A forked copy means you measure something you don't ship.
Unlabeled modest number narrative A low pass@1 is a feature of the story — the "before" — only if it's explicitly labeled the naive schema-dump baseline.

7 Guardrails for this step

Never (anti-patterns)

  • Compare SQL by string-match — result sets only via compare.py (CLAUDE.md §7).
  • Fork the pipeline for the harness — shared import, no drift (CLAUDE.md §3).
  • Put the terminal-state classifier in state.py — it lives in the harness/metrics.
  • Report a number without a RESULTS.md entry (now mandatory).

Always

  • Keep the slice frozen, seeded, stratified and checked in as an explicit ID list.
  • Validate the harness on trusted ground (payments gold) before BIRD.
  • Tie every reported number to model, slice ID, prompt version, date, commit.
  • Keep eval/ a peer of src/.
