1 Overview

The first Step-4 tracer bullet: a deterministic, pre-execution guardrail that vets candidate SQL on the sqlglot AST — and the fixture harness that measures it.

A safety check is only as good as the test that proves it. So this slice cuts the whole vertical at once: a read-only rule that rejects any write/DDL by AST type, never a keyword regex; the guard stage wired between generate and execute so a rejected candidate never touches a database; harness classification into the GUARDRAIL_REJECTED terminal state (upstream of scoring); a named-deliverable red-team fixture; and a reusable catch-rate measurement seam. Later issues only add rules and cases.

The gate is sqlglot-AST only — no LLM judge, no regex over SQL semantics (CLAUDE.md §4, §7) — which is exactly why its effectiveness can be stated as a number rather than asserted.

2 Key changes

pipeline/guard.py — the gate

  • guard_sql: the pure, deterministic core. Rejects INSERT/UPDATE/DELETE/MERGE/ CREATE/DROP/ALTER/TRUNCATE by AST type.
  • find() walks the whole subtree, so a write inside a CTE is caught; a SQLite REPLACE (parsed as a generic Command) is caught by verb.
  • guard: the thin stage wrapper that records the verdict on the RunState.

pipeline/graph.py + state.py

  • Pipeline is now generate → guard → execute; a reject skips execution.
  • RunState gains guard_rejected / guard_reason — facts the harness reads; the classifier stays in the harness (CLAUDE.md §3).

eval/redteam.py — measurement seam

  • Loads the labeled fixture, runs each case through guard_sql, aggregates verdict agreement + catch rate (caught / dangerous).
  • A peer of the comparator's golden-fixture proof; #35 reports its number to RESULTS.md.

eval/harness.py — classification

  • A guard-rejected run buckets GUARDRAIL_REJECTED first, and is never scored (no candidate result to compare) — scoring upstream of redaction preserved.

fixtures/redteam_guard/ — deliverable

  • read_only.json: write/DDL + benign cases, each with an expected verdict (and the rule that should fire).
  • Includes the AST-not-regex proof — a column literally named "delete" must pass.

tests/test_guard.py — three-layer proof

  • Fixture-driven verdicts · unit contract · wiring: an exploding engine proves execute is skipped on a reject.

5 Scope boundary

Read-only's job is strictly data/schema writes. Adjacent surfaces are deliberately left for their own slices so each guardrail is independently testable:

  • Dangerous-op (#33) — stacked statements, ATTACH/DETACH, write-bearing PRAGMA.
  • Cost/complexity (#34) — join count, missing LIMIT, cartesian products (heuristic-first, no EXPLAIN on SQLite).
  • Table-scope → Step 6 — needs a per-db allowed-tables list (schema metadata); not hardcoded provisionally here.
