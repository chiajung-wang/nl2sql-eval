1 Overview

The third guard rule: a heuristic complexity budget read straight off the AST — no EXPLAIN — that blocks runaway scans without false-rejecting a single legitimate query.

Read-only and dangerous-op are correctness/safety gates. The cost rule is a heuristic: it rejects query shapes that imply a runaway or abusive scan — a cartesian product, a join explosion, an unbounded SELECT * full-table dump. Heuristic-first by mandate: BIRD is SQLite, which has no cost-bearing EXPLAIN, and BIRD drives the headline numbers, so the signal comes from the AST, not the planner.

The sharp risk: this rule runs on the live pipeline, so a false positive would silently drop BIRD pass@1 — with no recovery until Step-5 correction. So the thresholds are calibrated against the frozen 50-question gold, and a test runs the gate over all 50 to prove none are rejected.

2 Key changes

guard.py — _check_cost

  • Cartesian: a join with no ON/USING and no WHERE.
  • Join explosion: more than MAX_JOINS (=4).
  • Unbounded SELECT *: star over a single base table, no WHERE, no LIMIT.
  • Added to DEFAULT_GUARD_RULES last (safety rules win the reason first).

Calibration over magic numbers

  • MAX_JOINS is a named constant calibrated to the gold (max 2 joins → 4 is headroom).
  • The unbounded check is narrow on purpose: COUNT(*), a star over a bounded subquery, and a star with GROUP BY are all excluded.

fixtures/redteam_guard/cost.json

  • Cartesian (comma / CROSS / 3-table) · join explosion · unbounded star — plus six benign allows mirroring legitimate BIRD shapes.

tests/test_guard.py

  • Per-branch units + the 50-gold calibration test that pins pass@1 safety + the two false-positive regressions found in review.

Thresholds are derived from the gold's actual shape, then a regression test pins them: calibration on gold is necessary but not sufficient, so the benign allow cases cover the legit non-gold shapes (subquery-wrapped star, GROUP BY star) a model might emit.
