Profiling-derived field metadata — let the data describe itself

Author: Chia-Jung Wang (@chiajung-wang) Issue: #140 Branch: step-12/issue-140-profiling-metadata → main Source: Shkapenyuk et al., arXiv:2505.19988v2 §2.1 (AT&T #1 BIRD)

1 Overview

The paper's most surprising result: profiling the data beats human-supplied metadata. (MiniDev, no hints: profiling 61.2 vs supplied 59.6; fused best 63.2.) Cryptic schemas hide format the data exposes — that CDSCode is a 14-char id, that Academic Year is 'YYYY-YYYY'. Step 11 ruled out the cheaper metadata moves (FK enrichment #112 was a null — the FKs were already in the DDL) but never tried data-derived field descriptions. This is the biggest build in the set; it lands the whole offline machinery, with the accuracy A/B deferred.

2 The pipeline — split by the determinism boundary

1 · profile (SQL stats)→ 2 · mechanical English→ 3 · LLM summary (offline)→ profiles/<db>.json cache→ 4 · selector → schema

Steps 1–2 are deterministic, no LLM — reproducible and offline-testable. Step 3 is the only model-touching step, run once, offline, and frozen to a version-controlled artifact the live pipeline only reads. Step 4's selector (METADATA_SOURCE) rides the chosen descriptions into the rendered schema.

3 The profiler recovers the paper's own examples

The deterministic profile → mechanical English faithfully surfaces what a cryptic name hides:

# render_column_english(profile("CDSCode"))
Column "CDSCode" (TEXT). No NULLs across 3 rows. All 3 non-NULL values are
distinct (unique). Values are exactly 14 characters long, all digits,
always beginning with "0110017000000". Ranges from "011…01" to "011…03".

# render_column_english(profile("AcademicYear"))
Values are exactly 9 characters long, mixed characters …
Ranges from "2013-2014" to "2014-2015".  # the 'YYYY-YYYY' shape

Per-column stats: counts, NULL/non-NULL, distinct, uniqueness, value shape (length range, character class, longest common prefix, min/max), and top-k values. The LLM step then reads "14 characters, all digits" and writes "a County-District-School identifier".

4 The metadata-source selector

METADATA_SOURCEthe schema render uses…
supplied (default)Human/SME descriptions only — the current behaviour; a db with no artifact degrades here cleanly.
profilingThe data-derived (profiled + LLM-summarized) description only.
fusedSupplied + profiling combined where they differ — the paper's best (supplied names the intent, profiling the format).

Wired into the BIRD eval's index-build (eval/eval_bird_rag.py) via resolve_column_descriptions(db_id) → build_schema_index(column_descriptions=…), so the env axis is active in a real run. Descriptions ride in as comma-safe leading comments on each column.

5 Two load-bearing boundaries (both enforced structurally)

boundaryhow it's held
Descriptions are prompt content onlyNever read by guard.py or eval/compare.py — those stay deterministic and data-independent, so scoring is untouched (CLAUDE.md §4).
Profiling is PII-aware (review fix)A redaction-policy column profiles shape-only (counts, distinct, length, character class) — never its raw values (no min/max/prefix/top-values), so raw PII can't reach the artifact, prompt, or a trace on the payments path (§5.3). BIRD (public, no policy) is a no-op.
