Literal→field steering — right value, wrong column

Author: Chia-Jung Wang (@chiajung-wang) Issue: #141 Branch: step-12/issue-141-literal-field → main Source: Shkapenyuk et al., arXiv:2505.19988v2 §3 (AT&T #1 BIRD)

1 Overview

The generator often picks the right value but the wrong field to constrain it against. Ask for the id of "Fresno County Office of Education" and it writes WHERE CountyName = '…' — but that string lives in District, so the query runs clean and returns the wrong rows (the ambiguous_column root cause #134 labels). The paper fixes it deterministically: index sampled field values, check whether each literal actually occurs in the column it's bound to, and if not, name the columns that do hold it and ask the model to rephrase.

2 The loop — recovering the paper's flip

generate SQL→ extract literals (AST)→ index lookup: is it on-column?→ off-column?→ steer: "occurs in District"→ regenerate 
# the paper's worked example, recovered by the check:
SELECT id FROM schools WHERE CountyName = 'Fresno County Office of Education'
      # → steer: "'Fresno County Office of Education' does not occur in CountyName;
      #          it occurs in schools.district. Constrain that column instead."
SELECT id FROM schools WHERE District  = 'Fresno County Office of Education'  # fixed

3 Deterministic where it must be, LLM only for the rephrase

stephow
Value index (value_index.py)A sampled value→column map (moderate sample, not full-column — the paper's scalability caution). PII columns are never indexed (mirrors #140's redaction boundary). Tracks which columns were sampled, so "not in this column" is distinguished from "column not indexed".
Literal extraction (literal_check.py)sqlglot AST — col = 'x' / col IN (…) bindings, alias-resolved. Never a regex over SQL (CLAUDE.md §4/§7).
The decisionMechanical set membership. Steers only when confident: the constrained column was sampled and lacks the literal while another column holds it — so a sampling miss can't spuriously steer an on-column literal.
The rephraseThe only LLM touch — it rides the existing correct.py loop within the capped retry budget.

4 A correction signal, never a lost run

Wired like #139's soundness stage — guard → soundness → literal_check → execute — with the same recoverable contract:

literal_check→ off-column + budget left→ correct_literal → generate | off-column + budget spent→ execute anyway

So a false steer costs at most a wasted retry, never a dropped run. Selectable via the LITERAL_STEER env axis, off by default (a default run is byte-identical); when on, the eval builds the value index and threads it through run_pipeline(value_index=…).
