1 Headline & goal

Quantify what retrieval is worth — and measure the failure mode that can't be fixed at runtime.

Add RAG over schema metadata (not documents), make it loop-aware, add the retrieval-recall eval axis, complete the guardrail with table-scope enforcement (whose data source now exists), and expand the slice to large-schema dbs to show the retrieval lift where it matters. The naive-baseline → retrieval lift is the second of the two sharpest findings (PRD §9, CLAUDE.md §5/§6/§7).

2 What to build

Schema index + pipeline/retrieve.py

  • Index table defs, column names/types, a few sample values per column (knowing status ∈ {failed, settled} changes the SQL), optional descriptions.
  • Retrieve only the relevant tables for this question, not the full dump.

Loop-aware re-trigger

  • A column/table-not-found error feeds back into retrieval (re-retrieve), not only generation.
  • Closes the asymmetry where everything else looped but retrieval was single-shot.

Retrieval-recall metric (metrics.py)

  • Recall of retrieved tables vs the gold query's actual tables.
  • How the silent wrong-schema failure gets measured even though it can't be fixed at runtime.

Table-scope guardrail (guard.py)

  • "Touches tables it shouldn't" via the per-db allowed-tables list that schema metadata now makes available.
  • Deferred here from Step 4 deliberately. Deterministic sqlglot AST — no regex, no LLM.

Slice expansion

  • Extend the frozen BIRD slice to large-schema dbs (still seeded/committed/stratified).
  • Where retrieval earns its keep vs the Step 3 naive baseline.

Retrieval feeds only the relevant tables into generation; a not-found error re-triggers retrieval (closing the single-shot asymmetry). Two axes come out: accuracy/lift (what retrieval is worth) and retrieval recall (the silent wrong-schema failure, measured not fixed).

5 Done when & results log

Done when: retrieval recall is reported alongside accuracy, the loop re-retrieves on not-found errors, and the retrieval lift (accuracy with retrieval vs the Step 3 naive-dump baseline) is recorded.

Append to RESULTS.md: the retrieval-recall number and, crucially, the naive-baseline → retrieval lift (before/after accuracy) with full config. The second of the two sharpest findings (CLAUDE.md §6/§7).

6 Pitfalls

PitfallSeverityWhy it bites
Trying to "fix" the silent failure scope Valid SQL on the wrong tables has no clean runtime fix — measure it with retrieval recall. Trying to fix it is trying to solve Text-to-SQL.
Unfrozen / unstratified slice repeatability Keep the slice frozen/seeded/stratified even as you expand it, or CI deltas become noisy.
Skipping retrieval "because payments is small" design Build it anyway — it's a deliberate design choice to demonstrate, and BIRD's large dbs genuinely need it.
Regex/LLM table-scope check determinism Table-scope is a sqlglot AST check against the per-db allowed list — never regex, never an LLM (CLAUDE.md §4/§7).

7 Guardrails for this step

Never (anti-patterns)

  • Fork the pipeline for retrieval — shared import, no drift.
  • Use regex/LLM for the table-scope guard.
  • Pretend to fix the silent wrong-schema case — measure it.
  • Let the expanded slice drift from frozen/seeded/stratified.

Always

  • Report retrieval recall alongside accuracy.
  • Record the naive → retrieval lift (before/after).
  • Re-retrieve on not-found errors, within the Step 5 budget.
  • Include sample values per column in the index.
