Loop-aware re-trigger — a not-found error re-retrieves a wider schema

Author: Chia-Jung Wang (@chiajung-wang) Issue: #46 Branch: step-6/issue-46-loop-aware-retrigger → main

1 Overview

Close the asymmetry Step 5 left behind: the correction loop retried generation but never retrieval. Now a column/table-not-found execution error feeds back into retrieve — widening the schema — not only into generate.

Issue 1 made retrieval single-shot: pick the relevant tables once, then loop on generation. But a too-narrow first retrieval is its own failure mode — if the table the question needs never made the cut, the generator reaches for a name that isn't there and execute returns no such table. Regenerating against the same narrow schema can't fix that. This issue routes the not-found error back into retrieval: re-retrieve with a widened table budget, then regenerate. Each not-found retry doubles coverage — max_tables → 2× → 4× → … — converging on the full dump at the widest, which is the safety net.

Crucially it stays inside the Step-5 capped budget. A re-retrieve consumes an attempt; it never adds one. The same max_attempts that bounds regeneration bounds re-retrieval — no second budget, no infinite loop.

2 Key changes

retrieve.py — the signal + the nudge

  • is_not_found_error — classifies the engine message (SQLite no such table/column, Postgres … does not exist). String matching, not SQL — sqlglot still owns semantics.
  • missing_identifier — pulls the bare reached-for name (ghost) from the error as a lexical nudge; not the message's stopwords.

schema_index.py — the widening lever

  • relevant_tables(..., floor=N) — guarantee at least N tables, padding from declaration order beyond the lexical picks (ranked picks always kept).
  • A large enough floor reaches the full schema — the primary recovery mechanism.

graph.py — re-trigger in the loop

  • On a not-found error: re-retrieve with floor = max_tables · 2ⁿ + the identifier hint, then regenerate.
  • Error captured before correct() clears it.
  • Gated on schema_index — the schema= baseline never re-retrieves.

Bounded, not bypassed

  • Re-retrieve lives inside the one while loop; attempts increments once per cycle and the attempts ≥ budget return fires first.
  • re_retrievals counts widenings; it is not a second budget.

A not-found error takes the re-retrieve path (widen → regenerate); any other execution error takes the plain regenerate path. Both consume one attempt from the same Step-5 budget, so the loop always terminates.
