Table-scope guardrail

Author: Chia-Jung Wang (@chiajung-wang) Issue: #48 Branch: step-6/issue-48-table-scope → main

1 Overview

Complete the guard gate: reject a candidate that touches a table outside this db's allowed set — the check deliberately deferred from Step 4 until the schema metadata existed.

Single-db per run (CLAUDE.md §5.8): a query must stay within its tagged db's tables. The new rule is a deterministic sqlglot-AST check — base table names vs the db's real tables (from the schema index), case-insensitive, CTE names excluded. It runs only when that metadata is supplied, so the naive full-dump path is untouched.

The interesting part is how it reconciles with the #46 re-trigger: an out-of-scope reference is the too-narrow-retrieval symptom, so rather than hard-stopping, a table-scope rejection feeds back into retrieval (widening) within the capped budget — exactly the "reject or feed back as a correction signal" the guardrail spec allows (§5.4).

2 Key changes

guard.py — the rule

  • _check_table_scope: referenced base tables (AST, CTE-excluded) − allowed set; reject any out-of-scope name. Case-insensitive. Runs after the schema-free rules, gated on allowed_tables.
  • guard() records the firing rule on state.guard_rule so the graph can branch.

graph.py — feedback reconciliation

  • A table_scope rejection re-triggers retrieval (widening) within budget; security rules still hard-stop.
  • At budget exhaustion, table-scope → terminal GUARDRAIL_REJECTED (never executed).

Fixture + loader

  • table_scope.json: out-of-scope rejects · in-scope/CTE/case-insensitive allows · read-only-precedence.
  • The red-team loader passes per-case allowed_tables.

Security preserved

  • An injected/out-of-scope table never executes (guard is pre-execution); it widens and retries, then terminates as rejected. Catch rate unchanged at 1.000.

An out-of-scope table is the too-narrow-retrieval symptom, so it widens and retries (recovery preserved from #46); the boundary is still enforced — it never reaches the database, and budget exhaustion is a terminal rejection.

4 Review fix

An independent review noted that wiring table-scope in left the genuine not-found execution re-retrieve branch (#46) untested — both not-found tests used an out-of-scope table (now intercepted pre-execution). Added a case with an in-scope table + missing column that actually executes, errors "no such column", and re-retrieves via the execution path — so both recovery paths stay covered.
