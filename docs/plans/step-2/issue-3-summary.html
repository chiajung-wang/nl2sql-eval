1 Overview

The four substantive comparison rules that let equally-correct queries pass while still catching real semantic errors — each proven by its own golden triple.

This PR fills the Issue-11 canonicalization pipeline with its first real rules, all in eval/compare.py and all deterministic: column matching by position, NULL-sentinel normalization, and float tolerance. Each is a transform applied to both sides, so it can only let a correct answer pass — never make a wrong one look right. compare() itself is untouched; the rules register through the existing register_rule() seam and join the new DEFAULT_RULES.

The fourth rule is the one that isn't there: multiset semantics are the default by omission of any de-dup rule, so a COUNT vs COUNT DISTINCT row-multiplicity difference stays distinct and scores wrong. Every relaxation and every boundary ships a (gold, candidate, expected_verdict) triple that pins the exact rule it exercises.

2 Key changes

column_position — match by position

  • Relabels columns to positional placeholders so an alias / rename / relabel of a correct query can't fail it.
  • Values transposed between positions still differ → caught.
  • Intentionally inert against the row-only verdict: compare() already matches values positionally — the rule names and logs that contract and is the seam for a future label-aware rule.

null_sentinel — one normal form for NULL

  • Every None collapses to NULL_SENTINEL so NULLs compare consistently across drivers and become hashable / orderable.
  • The sentinel is distinct from any real value — a NULL never silently equals 0, "", or the string "None".

float_tolerance — fixed, logged precision

  • Rounds float/Decimal cells to FLOAT_DECIMALS = 6 before comparison; insignificant noise (an AVG off in the 9th digit) passes, a genuinely different number fails.
  • bool (an int subclass) is left untouched; non-numeric cells pass through.
  • A module constant, not a per-call knob — keeps every verdict reproducible.

Multiset — the rule that's absent

  • No de-dup rule exists, so duplicates are kept and row multiplicity matters.
  • COUNT vs COUNT DISTINCT → incorrect; under set semantics it would wrongly pass.
  • Equal multiplicities on both sides → correct.

New DEFAULT_RULES

  • column_position → null_sentinel → float_tolerance → exact, always-on for a trustworthy scorer.
  • Kept explicit so every reported verdict names the exact canonicalization it ran under. Ordering (#12) and BIRD (#14) extend the same tuple.

Scope guard held

  • No row-ordering logic — that's Issue #12; _map_cells preserves order to avoid a double-sort.
  • No BIRD reconciliation — that's Issue #14. Deterministic throughout: no LLM, no regex for SQL semantics.
