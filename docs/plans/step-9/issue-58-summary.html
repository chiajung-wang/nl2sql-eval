Prompt-CI — pass@1/pass@k deltas on every prompt change

Author: Chia-Jung Wang (@chiajung-wang) Issue: #58 Branch: step-9/issue-58-eval-workflow → main

1 Overview

A prompt change automatically tells you whether you improved or regressed. Most portfolios never build this. On every PR that touches a prompt, a GitHub Action re-runs the harness on a frozen slice — with both the base and the PR prompt — and posts the pass@1/pass@k deltas to the job summary and a sticky PR comment.

The eval was built before the feature (PRD §9), so this is wiring, not invention: the workflow calls the same import-shared pipeline the harness already measures, over the same kind of frozen/seeded/ stratified slice the project has used since Step 3 — just small enough to run on every push.

Both prompts run on the same slice, model, and environment, so a delta is attributable to the prompt bytes alone — apples-to-apples, no committed baseline that can drift. The footnote prints both fingerprints; if they match, the comment says "no prompt change — noise" instead of a verdict.

4 The cost guard

Full BIRD per push is too slow and costly — the fixed small subset is the point. The prompt-CI slice is a frozen, seeded, stratified 12-question set (simple 6 / moderate 4 / challenging 2), drawn from the same small-schema dbs as Step 3 so the naive dump never overflows context. Per-push cost scales with size × k × 2 (base + PR), ≈ 72 completions. Stratified so a delta is a real regression, not an accidentally-all-easy sample.

The live eval is gated on ANTHROPIC_API_KEY + BIRD_DEV_URL (defer-API-key): without them the job posts a "skipped" note and passes, never failing a PR for missing secrets.
