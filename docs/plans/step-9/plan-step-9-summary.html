Prompt-CI/CD

Phase: Operations — the senior differentiator, live Depends on: Step 3 (batch harness) · Steps 3 & 6 (frozen slice) Unblocks: Step 10 (a showcase artifact for the blog)

1 Headline & goal

A prompt change automatically tells you whether you improved or regressed.

Externalize prompts as version-controlled templates and add a GitHub Action that runs the harness on a frozen, seeded, stratified slice whenever a prompt changes, posting the pass@1/pass@k deltas. Most portfolios never build this; it's a direct hit on "CI/CD for prompts and models" and LLMOps requirements (PRD §9, CLAUDE.md §4/§9).

2 What to build

Prompt templates (prompts/)

  • Jinja-style templates with variable substitution for injected schema / few-shots.
  • Structured so the static scaffold stays put; only meaningful edits show — clean CI diffs.

.github/workflows/eval.yml

  • On change to prompts/, run the harness against the frozen slice and post pass@1/pass@k deltas (PR comment or job summary).
  • The slice is seeded, checked in (explicit ID list), and stratified by BIRD difficulty — a delta means a real regression, not sampling variance.

Cost guard for CI

  • Keep the slice small enough that per-push LLM cost is acceptable; document the trade-off.
  • Full BIRD is too slow/costly per push — the frozen subset is the point.

Because the slice is frozen, seeded, and stratified, a posted delta is a real signal — a regression caught or an improvement confirmed — not sampling noise. The cost guard keeps the subset small enough to run on every push.

6 Pitfalls

PitfallSeverityWhy it bites
Random-per-run subset repeatability A random subset makes deltas indistinguishable from noise — the slice must be frozen, seeded, and committed.
Accidentally-all-easy slice signal Stratify by difficulty, or an all-easy slice hides real regressions.
Per-push API cost cost Mind per-push LLM cost — that's why the slice is a fixed small subset, not full BIRD.
Inlined prompts CI hygiene Prompts must live in prompts/ as templates — inlining in Python breaks the clean-diff premise of prompt-CI (CLAUDE.md §4).

7 Guardrails for this step

Never (anti-patterns)

  • Use a random-per-run slice — deltas become noise.
  • Let the slice drift to all-easy — regressions hide.
  • Inline prompts in Python.
  • Run full BIRD per push — cost explodes.

Always

  • Keep the slice frozen, seeded, stratified, committed.
  • Post pass@1/pass@k deltas, not just absolute numbers.
  • Pin the prompt version per run.
  • Document the cost trade-off.
