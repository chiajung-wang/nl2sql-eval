Widen the dev slice — a sharper ruler that decides the nulls

Author: Chia-Jung Wang (@chiajung-wang) Issue: #133 Branch: step-11/issue-133-widen-slice → main

1 Overview

Widening the slice doesn't add accuracy — it adds certainty. Most of Step 11's non-model levers landed inside the 50-question dev slice's ~0.05 noise floor — inconclusive, not negative. This adds step11-dev-wide, a frozen, seeded, stratified 250-question slice, so a +0.03 effect is distinguishable from jitter — the prerequisite for the table-selection levers (#134/#135).

4 The payoff — an inconclusive null becomes a decided one

The reason to widen: re-test FK-only schema enrichment (#112), whose dev result was a within-noise −0.020 — inconclusive, not negative.

# FK-only enrichment, step11-dev-wide (gemini-3.1-flash-lite)
naive  0.444 (111/250)   →   fks  0.456 (114/250)   lift +0.012   join/table bucket 48 → 49

A clean within-noise null at the tighter ±0.031 SE, target bucket flat. Read alongside #112's dev −0.020, FK-only enrichment looks like a null on both models — though that cross-comparison changed both model and slice, so it corroborates the null rather than strictly replaying it. Either way the wider slice did its job: it gives #134/#135 a substrate where a +0.03 effect would actually be visible.
