Env-configurable MODEL override — recorded, default pinned

Author: Chia-Jung Wang (@chiajung-wang) Issue: #117 Branch: step-11/issue-117-model-env → main

1 Overview

Select the generator model with one env var — without weakening reproducibility. The error analysis pointed at the model swap as the lever with real headroom (gemini-3-flash 0.540 vs sonnet 0.420). To experiment with a different generator across the runners, MODEL now overrides the model — but the discipline is preserved: the default stays pinned in code, and every runner records the model it actually ran.

3 The invariant that mattered: record == run

The core risk of threading a model through many runners is a record-vs-run mismatch — a runner that records the override but silently runs the default. The review caught exactly one:

# eval_bird_adaptive.py — make_adaptive_run_one (caught by review)
  run_pipeline(..., budget_tokens=budget_tokens, model=model_id())
  # recorded model_id() but ran the default until this line was added

Fixed, and an explicit scan confirmed every run_pipeline call in the threaded runners now passes model= — so a number can never name a model it didn't run.
