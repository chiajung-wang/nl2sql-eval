1 Overview

Delivers the Step 1 / Issue 3 deliverable: a small, high-trust set of hand-authored payments questions paired with gold answers — the trusted ground that Step 3 validates the harness against before it is ever pointed at BIRD. Ten verified Q/A pairs span easy lookups → joins → group-by aggregations over the Issue 2 payments schema, each carrying a gold_sql, a gold_result ({columns, rows}), gold_tables for retrieval-recall scoring, and difficulty/category tags.

The honest part is two independent provenance flags: machine_verified (the agent's claim, proven by executing every gold_sql against a seeded db) and human_reviewed (a reviewer's separate sign-off that the wording matches intent — the agent never self-ticks it). Correctness is established by execution, not assertion: a verify_gold.py harness reproduces 10/10 gold answers against a fresh Postgres 16 seed, and a CI-safe structural test guards the file's shape without a db.

2 Key changes

Dataset — the gold set

  • questions.json — 10 verified records over the payments schema, each with gold_sql, gold_result ({columns, rows}), gold_tables, difficulty, category, and authoring notes.
  • Carries two distinct provenance flags: machine_verified · execution-proven human_reviewed · reviewer sign-off
  • A _meta block records dataset/schema/seed paths and the verification provenance.

Loader (import surface)

  • questions.py — lru_cached load_questions() / load_meta() so the Step 3 harness imports the set rather than hardcoding the JSON path.

Verifier (real logic)

  • verify_gold.py — runs every gold_sql against a live seeded db and diffs the stored gold_result (column names + ordered rows); exits non-zero on any mismatch.
  • Normalizes Postgres Decimal → int/float to match JSON-stored gold; reuses load.get_engine() and PAYMENTS_DB_URL. The backing for machine_verified; never touches human_reviewed.

Tests & docs

  • test_payments_questions.py — CI-safe (no-db) structural guard: unique ids, required fields, gold_tables ⊆ schema, result-shape consistency, category coverage.
  • README.md — documents the load → verify_gold flow and the two-flag machine_verified / human_reviewed split.
