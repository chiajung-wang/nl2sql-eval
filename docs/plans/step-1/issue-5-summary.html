1 Overview

Closes the Step-1 Definition of Done: prove the machine runs end to end. A hand-verified payments seed question is fed through the import-shared pipeline (graph.run_pipeline: generate → execute → return) — the same loop the harness and demo use — its terminal state is classified, and the returned result is checked against the question's verified gold answer.

The gold check is deliberately value-level, not string-match: gold_matches compares row values and ignores column aliases, because two equally-correct queries can label the same value differently (CLAUDE.md domain rule 1). It is a Step-1 stand-in — the canonicalized, order-insensitive comparator lands in eval/compare.py at Step 2, so no competing comparator is built here.

Live-proven against seeded Postgres + a real model: pay-001/004/006 PASS as terminal success; a bad query buckets as execution_error_final. A follow-up commit (from code review) documents the terminal-state caveats and defers two cleanups to Step 2 — no logic change. No RESULTS.md entry: that discipline starts at Step 3.

2 Key changes

Eval harness & proof (real logic)

  • eval/prove_step1.py (new) — proof entrypoint; CLI over the Issue 3 seed set. Runs one question through run_pipeline, prints per-stage obs logs, SQL, result, terminal state, PASS/FAIL; exits non-zero on mismatch.
  • gold_matches() — value-level row comparison, aliases ignored, driver Decimals normalized to match gold ints.
  • eval/harness.py — minimal classify_terminal_state covering the two reachable states (success / execution_error_final). Classifier lives in the harness, never in state.py (CLAUDE.md §3).

Tests (deterministic cores)

  • tests/test_terminal_classify.py (new) — CI-safe (no db, no network): exercises the classifier and gold_matches over hand-built RunStates.
  • Covers alias-ignoring, Postgres Decimal→int normalization, and wrong-value rejection.

Docs & review follow-up

  • README.md — proof command added to Usage; prove_step1.py added to Project Structure; harness-CLI "intended interface" caveat rescoped.
  • Review follow-up: harness docstring now notes a generation gap also buckets as execution_error_final at Step 1; TODO(step-2)s for the redaction-exit split and a shared normalizer.
