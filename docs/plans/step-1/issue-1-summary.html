1 Overview

This PR stands up the foundation slice of nl2sql-eval — a guardrailed agentic NL-to-SQL system whose centerpiece is the evaluation harness, not the agent. It commits the uv-managed project and the complete PRD §8 module tree as importable stubs, so every later slice has a home and all imports resolve.

The only modules with real content are state.py (the RunState dataclass plus the full six-value TerminalState enum, defined up front so the module never needs reshaping) and the thin obs structured-logging seam. No pipeline behavior, retrieval, guarding, LLM calls, or UI ship here — those are deliberately out of scope for the skeleton.

3 Architecture established

The skeleton wires the target architecture as stubs: a single import-shared pipeline consumed by both the eval harness and the demo, with the two critical exits (raw verified result for scoring, presented result for display) and the capped self-correction loop in place for later steps to fill in.
