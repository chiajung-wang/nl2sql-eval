1 Overview

Stands up the payments-platform demo database that the demo and the later guardrail / redaction work are built around — a local Postgres (via Docker) with a small but realistic, FK-consistent seed. The dataset deliberately carries PII columns and a write-sensitive ledger so later steps have concrete material to redact (Step 8) and guard against writes (Step 4).

Scope is dataset bootstrap only: DDL, seed, and an idempotent SQLAlchemy loader under eval/datasets/payments/ (per PRD §8). The pipeline's multi-engine executor stays a stub for issue 4. The two commits add the database and a follow-up that drops a PII column from the loader's verify output and records a ledger-ordering caveat for the issue-3 gold set.

2 Key changes

Database — DDL & seed

  • schema.sql — idempotent DDL for 7 tables: users, merchants, payment_methods, transactions, refunds, disputes, ledger. Drops in FK order, recreates.
  • seed.sql — FK-consistent seed: 6 users · 4 merchants · 7 methods · 14 transactions · 2 refunds · 2 disputes · 12 ledger entries with a coherent running balance.
  • Carries: PII · users.email/full_name/phone PII · card last4/brand/exp write-sensitive · ledger

Loader (real logic)

  • load.py — SQLAlchemy bootstrap via PAYMENTS_DB_URL; applies DDL + seed in one transaction; idempotent; verifies with row counts and a sample join.
  • Verify output selects user id + country, never PII columns (CLAUDE.md §5.3 — raw PII must never reach logs/traces).

Tooling & infra

  • docker-compose.yml — Postgres 16 with healthcheck + named volume.
  • pyproject.toml — adds sqlalchemy>=2.0 and psycopg2-binary>=2.9; uv.lock updated in step.
  • .env.example — PAYMENTS_DB_URL matching the compose creds.

Docs

  • README.md — config, project-structure, and quickstart updates.
  • issue-3-…seed-set.md — note: ledger.balance_after_cents only coheres in id order (timestamps aren't monotonic with id).
